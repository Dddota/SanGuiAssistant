# 自动刷战功流程设计

## 功能目标

在大地图中，自动从「情报 → 城池战事」列表中识别可攻打地点，优先攻打**敌众我寡且距离近**的战斗地点，自动补兵、出征、结算，反复刷取战功。

> 与归心（纯 pipeline JSON 声明式）不同，战功采用**进阶四层架构**：
> `Tab UI → TaskRunner → ZhanGongEngine（纯 Python 逻辑）→ MaaController → 设备`
>
> 因为需要 OCR 解析表格、动态评分排序、复杂循环判断，pipeline 声明式表达力不足，故核心逻辑写在引擎 (`app/core/zhan_gong_engine.py`) 中；pipeline JSON (`app/assets/pipeline/zhan_gong.json`) 仅作为辅助模板参考。

## 游戏内流程（1280x720 横屏）

1. **大地图**点击「情报」按钮 → 打开情报面板。
2. 切换「城池战事」页签 → 右侧出现**战斗地点表格**，每行一个地点，包含 5 列：
   `战争状态 | 敌方 | 我方队伍数量 | 敌方队伍数量 | 战斗地点`
   - 敌方列示例：`进攻吴国乐安南`
   - 队伍数量列示例：`0`（我方）、`1734+63`（敌方，驻守+增援，`+` 连接需求和）
3. 点击某个战斗地点 → 地图定位到该城，**右侧弹出队伍面板**，每个队伍卡片含：队伍名（如"赵云队"）、战力、状态（驻守中/重伤 XX 秒等）、预计耗时（距离依据）、攻打按钮、补兵按钮。
4. 选中目标队伍 → （可选自动补兵）→ 点「攻打」→ 确认出征 → 等战斗结算 → 关闭结果 → 回到列表打下一个。

## 自动化流程

```
大地图 → 点情报 → 切城池战事
  → OCR 读取战斗地点表格（分组解析）
  → 评分排序（优先城市 +100 / 敌众我寡加分 / 耗时短加分）
  → 逐个攻打 rank 列表：
      点战斗地点 → 解析右侧队伍面板 → 选目标队伍
        →（若重伤，等待恢复倒计时）
        →（若启用自动补兵，点补兵；无粮则放弃该地）
        → 点攻打 → 确认出征 → 等战斗结算 → 关结果
  → 回到城池战事列表，排除已打地点，继续下一个
  → 直到无可攻打地点 / 达最大次数 / 手动停止
```

## 结束判定

- 城池战事列表无尚未攻打的可攻打地点。
- 已达最大攻打次数 `max_attacks`（默认 20）。
- 目标队伍无粮/重伤无法恢复/不可出战。
- 用户手动点击「停止」。

## 异常处理

- **列边界识别失败**：表头关键词未命中时，`col_edges` 为空 → 走 `_parse_row_fallback()` 智能兜底，从整行文本分离地点名与敌/我兵力。
- **补兵按钮未识别**：多关键词（补兵/征兵/募兵/补给/补员）+ 攻打按钮左侧 80px 兜底；仍失败则跳过补兵直接攻打并输出日志。
- **不可攻打**：识别到"无法攻打/不能出兵/距离太远/兵力不足"等关键词 → 放弃该地点。
- **距离太远**：目标队伍预计耗时 > `max_cost_time`（默认 600s）→ 放弃。
- **无粮食**：补兵后识别到"粮食不足/无粮食"等 → 结束该地点攻打。
- **重伤**：读取恢复倒计时（`XX秒` 或 `MM:SS`），等待恢复后再攻。

## 参数配置（Tab UI → `_build_params()`）

| 参数 | 键 | 默认 | 说明 |
|---|---|---|---|
| 优先城市 | `priority_cities` | `[]` | 逗号分隔，命中则评分 +100 |
| 敌我兵力倍率阈值 | `enemy_ratio` | `2.0` | 敌方兵力 > 我方 ×2 才视为值得打 |
| 最大耗时 | `max_cost_time` | `600` | 距离开限（秒），超过放弃 |
| 出战队伍名称 | `team_name` | `""` | 优先按名称匹配，留空用序号 |
| 出战队伍序号 | `team_index` | `1` | 名称匹配失败时用序号兜底 |

> 说明：补兵逻辑始终生效（检测到兵力不足即补兵，不再有 `auto_supply` 开关），补兵后验证血条是否恢复，未恢复则停止攻打。

引擎内部参数（`__init__` 读取，Tab 未直接暴露）：`list_roi`、`team_panel_roi`、`wait_anim`、`max_attacks=20`、`max_locations=50`、`max_attacks_per_loc=15`。

## 评分算法（`_score`）

```
score = 0
命中优先城市            → +100
敌我兵力都存在：
  敌我比 >= enemy_ratio → + min(ratio*10, 100)
  否则                 → + ratio*5
有敌情但不知我          → +30
只有我无敌              → -20
敌我都未知              → -10（降权）
已读耗时 cost_time>0   → + max(0, 100 - cost_time/6)   （耗时越短分越高）
未判断耗时              → +10
```

排序后输出前 10 个地点的日志（名称、敌/我兵力、耗时、评分），让用户看到数量与距离对比。

## Pipeline 节点结构（`app/assets/pipeline/zhan_gong.json`）

```
zhan_gong_start         # 入口
  └─ zhan_gong_find_intel      # 找情报按钮 → 点击
       └─ zhan_gong_find_city_war  # 找城池战事页签 → 点击
            └─ zhan_gong_engine_loop  # 循环
                 ├─ zhan_gong_find_attack    # 找攻打按钮
                 │    └─ zhan_gong_confirm_attack  # 确认出征
                 │         └─ zhan_gong_battle_done   # 等待战斗
                 │              └─ zhan_gong_dismiss_result  # 关结果
                 │                   └─ 回到 engine_loop
                 └─ zhan_gong_finished  # 结束
```

> 注意：pipeline 为早期简单流程版本，目前主逻辑已迁移到 `zhan_gong_engine.py`，pipeline 节点主要作为引擎内部模板匹配辅助。
